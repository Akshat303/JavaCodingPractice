## QUESTION TYPES — INCLUDE ALL RELEVANT TYPES

Create a balanced mixture of the following MCQ types for every subtopic. Do not restrict the question bank to definition-based or theory-only questions.

### 1. Conceptual and Fundamental MCQs
- Test core definitions, principles, rules, and terminology.
- Ask what a concept means, why it is used, and how it works.
- Cover the differences between related concepts.
- Test understanding of the underlying concepts rather than memorization alone.

### 2. Summary-Based and Revision MCQs
- Create questions based on the essential concepts, rules, key points, and takeaways of the subtopic.
- Test whether a learner can identify the most accurate summary of a concept.
- Include questions such as:
  - Which statement best summarizes this concept?
  - Which statements about this topic are correct?
  - Which option correctly describes the relationship between these concepts?
  - Which rule should a developer remember when using this feature?
- For single-answer questions, ensure that exactly one option is correct.
- Do not use vague questions or options that are merely different but equally valid summaries.

### 3. Code Output Prediction MCQs
- Present valid Java code snippets and ask what the program prints or what happens during execution.
- Cover variables, data types, operators, conditions, loops, methods, classes, objects, inheritance, polymorphism, exceptions, strings, collections, and other concepts when relevant to the supplied subtopics.
- Include normal execution, boundary conditions, and relevant edge cases.
- Use multiple lines of code where needed to test actual understanding.
- Ensure that the correct output is verified carefully.
- Distinguish clearly between compile-time errors, runtime exceptions, and normal output.
- Do not include invalid code unless the question explicitly asks the learner to identify or predict a compilation error.

### 4. Pseudocode and Logic-Based MCQs
- Include language-independent or Java-inspired pseudocode when appropriate.
- Ask learners to predict the output, final variable values, number of iterations, execution sequence, or result of an algorithm.
- Cover conditions, loops, nested loops, counters, accumulators, branching, and basic algorithmic reasoning when relevant.
- Include tracing questions that require learners to follow the logic step by step.
- Clearly define any nonstandard pseudocode conventions needed to answer the question.
- Ensure pseudocode has one unambiguous answer.

### 5. Programming and Coding Scenario MCQs
- Present short programming problems, incomplete Java programs, or realistic developer scenarios.
- Ask which code snippet correctly implements a requirement.
- Test how a concept is applied in an actual program.
- Include questions about choosing the correct implementation, method call, command, declaration, or program structure.
- Use practical examples involving input validation, data processing, object creation, method calls, and error handling when relevant.
- Keep the code concise enough for an MCQ but sufficiently meaningful to test programming ability.

### 6. Code Completion and Missing-Code MCQs
- Provide a partially completed Java program or code snippet.
- Ask which statement, expression, method implementation, or command should replace the missing part.
- Test syntax, logic, API usage, and correct program behavior.
- Ensure only one option completes the requirement correctly.

### 7. Error Detection and Code Correction MCQs
- Present code containing a specific compilation error, runtime problem, or logical mistake.
- Ask the learner to identify the cause or select the correct fix.
- Distinguish syntax errors, type errors, access violations, incorrect API usage, and logical errors.
- Ensure the question specifies the intended behavior when necessary.
- Do not make multiple options correct because of unrelated errors.

### 8. Practical Command-Line and Environment MCQs
- For topics involving Java setup, compilation, execution, packages, classpaths, modules, environment variables, or command-line arguments, include realistic terminal commands and execution scenarios.
- Test command order, file locations, class names, paths, arguments, environment configuration, and expected behavior.
- Ensure commands are accurate for the stated operating system or clearly specify platform assumptions.
- Do not assume a particular operating system unless the question explicitly states it.

### 9. Comparison and Decision-Making MCQs
- Test important distinctions between related concepts.
- Ask which approach is appropriate for a particular requirement and why.
- Include practical trade-offs and common misconceptions.
- Avoid superficial questions that only change the wording of another question.

### 10. Edge-Case and Interview-Trap MCQs
- Include carefully selected boundary conditions, common misconceptions, tricky execution scenarios, and frequently misunderstood rules.
- Test default behavior, invalid input, scope, accessibility, initialization order, type conversion, and version-dependent behavior when relevant.
- Use interview-style traps without relying on obscure trivia or ambiguous wording.

## QUESTION DIFFICULTY

Include an appropriate balance of:

- **Easy:** Basic understanding, definitions, syntax, and straightforward examples.
- **Intermediate:** Multi-step reasoning, code tracing, practical application, and comparisons.
- **Advanced:** Edge cases, subtle language rules, complex execution flow, and interview-level reasoning.

Difficulty should emerge from the reasoning required, not from unnecessarily complicated code or confusing wording.

- `"answer"`: A zero-based integer from `0` to `3`, indicating the correct option's position.
