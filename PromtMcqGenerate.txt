## QUESTION TYPES — MIX ALL RELEVANT TYPES IN EVERY SUBTOPIC
====================================================================

Do not make the bank theory-only. For each subtopic include a balanced mix of:

1. Conceptual and fundamental: definitions, rules, terminology, why/how a feature works.
2. Summary / revision: "Which statement best summarizes...", "Which rule must a developer remember...". Exactly one option must be correct.
3. Code output prediction: valid Java code; ask what is printed or what happens (normal flow, boundaries, edge cases). Distinguish clearly between compile-time errors, runtime exceptions, and normal output.
4. Pseudocode and logic tracing: loop counts, final variable values, execution order, algorithm results. Define any non-standard pseudocode convention in the question (for example "/ means integer division").
5. Programming / coding scenario: realistic mini-requirements; ask which implementation is correct.
6. Code completion: code with a blank marked ____ ; only one option completes the requirement correctly.
7. Error detection and correction: a specific compile error, runtime problem, or logic bug; ask for the cause or the fix. Do not let unrelated errors make several options correct.
8. Command-line / environment (only when the subtopic involves compiling, running, classpath, packages, modules, environment variables, or arguments): realistic commands with stated platform assumptions.
9. Comparison and decision-making: when to use which construct, trade-offs, common misconceptions.
10. Edge-case and interview-trap: boundary values, default behavior, scope, type conversion, short-circuiting, initialization order, version-dependent behavior. Use well-known interview traps, not obscure trivia.

## CODE RULES (very important)
====================================================================

A. Keep the question text and the code SEPARATE.
   - "question" contains only the prose (for example "What is the output?").
   - The code goes in the "code" field. Never paste code into "question".
   - Questions with no code must NOT contain the three code fields at all.

B. Code fields (add all three, or none):
   - "codeLanguage": "java" for Java code.
       "pseudocode" for pseudocode.
       "bash" for Linux/macOS terminal commands, "powershell" or "cmd" for Windows commands.
       Use another lowercase language name only when really needed (for example "xml", "json", "properties").
   - "codeFileName": the file name that matches the code.
       Java: the name of the public or main class + ".java" (for example "Example.java", or "Calls.java" when the class is Calls).
       Pseudocode: "Pseudocode.txt". Bash: "commands.sh". PowerShell/cmd: "commands.ps1" / "commands.cmd".
   - "code": the code as one JSON string, using \n for new lines, and four spaces for indentation.

C. Java code must be a COMPLETE, runnable class so a learner can copy it and run it:
   - Include imports when needed (java.util.*, java.util.Scanner, and so on).
   - Put statements inside "public static void main(String[] args)" (or inside suitable methods called from main).
   - Method-only questions still need a class around the methods and a main that calls them.
   - Use the same class name as codeFileName.
   - Exceptions: (1) code containing a blank ____ for a code-completion question, and (2) code that is deliberately wrong for a compile-error question. Everything else must compile and run exactly as the question states.
   - Multiple files: put every file in "code", separated by a line like  // ---- File: Shape.java ----  and set "codeFileName" to the file that contains main.

D. Options may contain short code (for example a code-completion or "which implementation is correct" question). In that case keep the code inside the option strings and still keep the question prose in "question". If the surrounding scenario also needs shared code, put it in the "code" field.

E. Programs that read input (Scanner) are allowed only when the input is not needed to answer the question. Prefer hard-coded values.

F. Never write infinite-loop or non-terminating output questions that print forever. For "runs forever" questions, make it clear in the question or options that the behavior is a non-terminating loop (for example the program never reaches the last statement).
